# 三级 KV 放置实验

使用第 05 组保存的 SciFact 检索输入，经正式 `memmgr.inference.server` 入口比较三组策略：

- `lru`：原生 CPU LRU，加同一文件层的有界 SSD LRU。
- `learned`：已有 GBDT 准入与 CPU 预测淘汰，接纳的数据沿原生路径级联到 SSD。
- `placement`：使用 GBDT 复用概率、下次复用间隔、真实路径成本和替换损失，选择 CPU 保留、SSD 保存或丢弃。

三组使用相同的 GPU、CPU、SSD 物理预算和传输实现。vLLM 原生文件层没有容量淘汰，本实验为文件层加入容量上限及 LRU，作为可比较的分层基线。

## 环境与运行

使用独占的 Linux / WSL NVIDIA GPU、本地 O_DIRECT SSD，以及项目 `requirements.in`、`constraints.txt` 中的固定依赖。模型固定为 Qwen2.5-1.5B-Instruct FP16，revision 为 `989aa7980e4cf806f80c7fef2b1adb7bc71aa306`。

`PYTHON` 指向项目解释器；`MODEL` 指向固定模型快照；`RUNTIME/hf` 为已有 Hugging Face 缓存。先按第 05 组指南生成真实 `prompts.json`。

```bash
"$PYTHON" experiment_raa/06_kv_placement/run_placement.py \
  --model "$MODEL" --runtime "$RUNTIME" \
  --prompts .agent/ssd-results/prompts.json \
  --output .agent/placement-results

"$PYTHON" experiment_raa/06_kv_placement/review_placement.py \
  .agent/placement-results
```

结果须位于项目 `.agent` 内，所在文件系统须支持 O_DIRECT。默认端口 `18086`，使用 `--port` 修改。目录须尚不存在。入口只管理自己启动的服务。

可先用 `--stage smoke` 检查 20 条真实请求；正式运行使用另一个输出目录。需要分开执行时，先运行 `--stage collect`，随后在相同输出目录运行 `--stage evaluate`。评价前核对源码和输入摘要，不接受中途更改。

## 固定条件

- vLLM 0.29.0、64-token 块、LBHNC、eager、单 worker、单序列，显式开启 batch invariance。
- GPU KV 预算 58 MiB，CPU 128 MiB，SSD 224 MiB；实际块数由引擎和文件层记录。
- 每条请求输出 32 token，固定温度与随机种子。各组回放同轮完全相同的输入。
- 问题按 ID 分成互不重叠的采集组和评价组。采集覆盖稳定热点、扫描干扰、热点切换、长间隔及三种输入长度的恢复。
- GBDT 标签为之后 24 条请求内是否再次访问，并为正样本训练下次复用间隔回归器。间隔以串行请求数计量；按时间切分训练与验证，剔除跨分区标签。成本专用序列不参与模型训练；评价前冻结两个模型和成本。
- 评价执行两轮独立请求序列，第二轮反转策略执行顺序。

## 成本与放置

从真实指标取得 prefill 时间、计算 token、GPU↔CPU DMA 作业数、载荷及计时；SSD 成本来自真实文件作业的完成时间。SSD 写入拟合仅计新增文件，已存在文件由原生实现跳过。

五条路径分别以非负最小二乘拟合：`时间 = 固定作业成本 × 作业数 + 每块成本 × 块数`。成本表保存原始观测、拟合误差和来源摘要。运行设备、数值模式、实际容量、模型与源码身份须一致。超过校准的最大前缀长度直接报错。

联合策略以未来观察窗口内的一次复用估计收益：各块复用概率乘以可节省的边际重算时间，减去预计读取成本、新增写入成本及被替换块的收益损失。替换损失按“新前缀预计复用间隔 ÷ 驻留块预计复用间隔”缩放，反映等待期间的容量占用。驻留块的固定读取开销按该路径校准的中位作业大小分摊。收益未超过 `margin_ms` 时放弃新增缓存。

CPU 物理预算包含 SSD 中转。联合策略预留一个校准最大前缀的槽位；其余空间用于 CPU 保留。SSD 写入与恢复仍使用原生异步作业、DMA 和引用计数。只在请求结束、SSD 写入完成且引用归零后释放中转块。

放置按请求完整前缀冻结一次，已有 CPU 保留块继续保留，其余块统一选择目标。已有 SSD 文件可以继续复用。SSD 淘汰避开当前请求及在途作业；联合策略优先淘汰低收益叶块，减少前缀截断。GPU 替换由原生引擎负责。

联合策略当前要求串行请求和空 SSD 会话目录。历史上限为 4096 个块身份，容量不满足该边界时直接报错。`lru`、`learned` 继续支持同一命名空间的 SSD 文件恢复。

## 输出与复核

- `environment.json`、`*-trace*.json`：执行源码、输入来源摘要与固定请求序列。
- `collect/`：真实采集响应、原始指标、块事件、服务日志和资源采样。
- `model/`、`costs.json`：冻结的复用分类器、间隔回归器、时间分区样本及真实路径成本。
- `e*-*/`：正式服务配置、响应、逐请求指标、异步事件和实际进程 I/O。
- `summary.json`：复算得到的 TTFT、中位配对节省、P95、计算 token、四条路径的传输载荷、放置次数与驻留量。

复核器重建前缀历史和 CPU 引用、SSD 作业、文件淘汰及驻留状态，核对每次传输的块身份与指标字节数，并检查同容量、评价问题独立性和生成一致性。

客户端 TTFT 包含实际策略及审计开销；请求间指标等待不计入单次时延。原生传输载荷可包含已存在文件的级联检查，实际设备 I/O 单独保存在进程采样中。成本模型描述路径作业时间，异步重叠和调度开销由端到端评价体现。
