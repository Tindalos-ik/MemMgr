# 实验设计

## 1. 数据与抽样

使用 BEIR SciFact：语料为论文标题和摘要，查询为科学论断，相关性标签采用官方 test qrels。数据来源与许可见[实测报告](../reports/本机基线实测报告.md#数据)。

从同时存在于查询文件和 qrels 的问题中，用种子 7 抽取 30 个，再按 ID 字符串排序。三层语料逐级扩充，每层均保留所选问题的全部正相关文献，其余文献随机补足。

独立检索使用全部 30 个问题，问答取前 8 个。每个条件先用首个问题预热 1 次，再正式重复 2 次；两次使用相同问题与顺序。重复记录的条数与独立问题数分别统计。

## 2. 实验分组

### 语料规模与检索

每层首次导入 1 次，随后以 K=3、C=1 检索。三层共 180 条正式检索记录。

| 语料 | 文献数（篇） | 正式检索记录 |
|---|---:|---:|
| small | 256 | 60 |
| medium | 1500 | 60 |
| full | 5183 | 60 |

### 端到端问答

全部使用 small 语料，每组 16 条正式记录，共 112 条。第 2 组为参照，其余各组只改变 B、K、C 中一项。

| 组别 | B：完整输入预算（token） | K：候选文本块数 | C：客户端并发 |
|---|---:|---:|---:|
| 1 | 512 | 3 | 1 |
| 2（参照） | 1024 | 3 | 1 |
| 3 | 1536 | 3 | 1 |
| 4 | 1024 | 1 | 1 |
| 5 | 1024 | 5 | 1 |
| 6 | 1024 | 3 | 2 |
| 7 | 1024 | 3 | 4 |

各组按固定次序执行，服务持续运行并共享前缀缓存。比较延迟时，同时查看实际输入、输出长度与缓存条件。

## 3. 固定参数

| 项目 | 设置 |
|---|---|
| 向量编码 | BAAI/bge-small-en-v1.5，CPU，归一化，batch size 16；查询添加配置中的检索前缀 |
| 文本分块 | 标题与正文合并，用 BGE tokenizer 分块；块长 384 token，重叠 32 token |
| 向量数据库 | Chroma，cosine distance，距离越小越相关 |
| 生成模型 | Qwen2.5-1.5B-Instruct，FP16，eager |
| 服务端调度 | `max_model_len=2048`、`max_num_seqs=1`、`gpu_memory_utilization=0.8` |
| 生成参数 | 输出上限 128 token，temperature 0，seed 7，HTTP timeout 180 秒 |

完整配置见 [baseline.json](../config/baseline.json)、[server.json](../config/server.json)，模型 revision 见 [models.json](../config/models.json)。

- **B** 包含系统提示、问题、证据、引用标记和完整聊天模板，有效上限为 `min(B, max_model_len - max_tokens)`。超预算时裁切当前证据并停止追加；实际输入可小于 B。
- **K** 为 Chroma 返回的文本块上限。按文档 ID 去重，只保留排名最前的块，不追加查询补足文档数。
- **C** 为客户端同时接纳的请求数，覆盖检索到生成全程；查询编码另有串行锁。服务端固定单序列，C=2/4 包含服务端等待。

## 4. 指标与统计

### 检索与回答

相关文档集合 R 取 qrels 中分值大于 0 的文档；D 为去重后的至多 K 篇检索结果，`rel(i)` 为第 i 篇是否相关（1 或 0）。

- `Recall@K = |D ∩ R| / max(1, |R|)`。
- `DCG@K = Σ rel(i) / log2(i + 1)`，i 从 1 起；`IDCG@K` 为前 `min(|R|, K)` 项全部相关时的 DCG；`nDCG@K = DCG@K / max(IDCG@K, 1e-12)`。

评分使用 `retrieved_doc_ids`；预算裁切后的实际证据记录在 `included_doc_ids`。改变 B 不直接改变检索评分。Recall 与 nDCG 衡量文档相关性，回答正确性需另行评价。

输入与输出 token 统计采用服务端 `usage`；本地计数和估值单列保存。`truncated` 表示输入证据裁切，`finish_reason=length` 表示输出达到上限。

引用遵从率为含 `[DOC document_id]` 引用的正式回答数占比；来源检查核对引用 ID 是否属于 `included_doc_ids`。引用形式与来源检查不评价证据是否支持回答。

### 耗时

全部使用单调时钟，单位为秒。TTFT 以收到首个非空正文内容块为准。

| 指标 / 字段 | 计时范围 |
|---|---|
| 应用排队 `queue_wait_seconds` | 请求协程开始至取得客户端信号量 |
| 问答 E2E `e2e_total_seconds` | 取得信号量至生成请求返回，含检索与生成，不含应用排队和结果落盘 |
| 调度总耗时 `scheduled_total_seconds` | 请求协程开始至生成请求返回 |
| 应用 TTFT `e2e_ttft_seconds` | 取得信号量至首个正文块 |
| 模型 TTFT `model_ttft_seconds` | 发起生成 HTTP 请求至首个正文块 |
| 生成阶段 `model_total_seconds` | 发起生成 HTTP 请求至流式响应结束 |
| 查询编码 `query_embedding_seconds` | 提交编码线程至向量返回，含线程与编码锁等待 |
| 数据库检索 `retrieval_seconds` | 查询向量就绪后提交 Chroma 查询至结果返回 |
| 上下文组织 `context_assembly_seconds` | 提示词组装、预算核验与证据裁切 |
| 独立检索 `full_retrieval_seconds` | 接纳后开始编码至去重与评分完成 |

模型 TTFT 和生成阶段包含网络与服务端等待。vLLM 模型加载耗时、加载显存另从启动日志读取。

导入的 `full_seconds` 包含初始化、文本准备、编码、写入和最终校验；`measured_wall_seconds` 另包含清单保存。分项记录在索引清单中，总吞吐为最终块数除以 `full_seconds`，单位块/秒。每层导入只有一次观测。

### 吞吐与汇总

- 正式统计筛选 `phase=formal`、`status=ok`，排除预热。`usage_missing` 表示传输成功但服务端用量不全；运行时成功数可能包含它，报告复算成功数将其排除。
- 逐请求指标报告平均数、中位数、最近秩 P95；P95 取排序后的第 `ceil(0.95 × n)` 项。每组问答 n=16，P95 为最大值；每层检索 n=60，P95 为第 57 项。缺失值不计入对应指标的 n，统计结果用于描述本轮观测。
- 批次墙钟从提交全部请求前计至全部返回，含应用排队，不含初始化和预热。合并重复时，请求吞吐为成功数之和除以墙钟之和（请求/秒），输出吞吐为服务端输出 token 总数除以墙钟之和（token/秒）。
- 单请求生成速率为 `output_tokens_server / model_total_seconds`，单位 token/秒，单列统计。

### Web 与 CLI

交互问答的 E2E 包含按需加载编码器和 tokenizer；正式批次在请求计时前完成初始化，比较时需区分这两种范围。

Web 实验启用 `_web_fail_fast`，请求失败后保存错误并终止该任务。Web 纯检索按请求完成即落盘，批次墙钟包含写入；CLI 纯检索在批次结束后写入。中断运行缺失的批次吞吐保留为空。

## 5. 资源采样

采样覆盖预热和正式请求；检索与问答的编码器、tokenizer 初始化在采样前，索引初始化在采样内。主机目标周期 1 秒，Docker 目标周期 5 秒，实际间隔随采集耗时变化。

| 资源 | 范围与口径 |
|---|---|
| GPU | 整张设备的利用率（%）和已用显存（MiB）采样峰值，含其他进程及服务预留 |
| 内存与 Swap | WSL 系统已用字节数峰值 |
| Python RSS | 测量进程及子进程 RSS 求和后的峰值，单位字节，共享页可能重复计数 |
| vLLM RSS | 配置 PID 及子进程的 RSS 总和峰值（字节）；未配置 PID 时标明未采集 |
| Chroma | 指定容器的 Docker CPU（%）和内存（MiB）采样峰值；卷大小为启动时快照（字节） |
| 磁盘 I/O | WSL 系统累计读写字节数的末次减首次，含其他系统活动 |

资源峰值可能来自不同时刻；离散采样可能遗漏瞬时峰值。缺失与失败保留原状态，不补零。`1 MiB = 2^20` 字节，`1 GiB = 2^30` 字节。

## 6. 执行与查看结果

先按[部署说明](部署.md)安装依赖、下载模型并启动 vLLM 与 Chroma。以下命令在 Linux / WSL 项目根目录执行：

`prepare` 会重写目标数据目录，复跑前确认配置。测量首次导入需独立的数据目录和持久化环境；已有索引会复用，只记录本次查找耗时，并关联历史首次导入来源。保留已有数据和正式结果。

```bash
export PYTHON="$PWD/.venv/bin/python"
"$PYTHON" -m memmgr --config config/baseline.json prepare
"$PYTHON" scripts/run_baseline.py --config config/baseline.json
```

执行顺序为 small、medium、full 各自导入后检索，再进行七组问答。七组 B/K/C 固定在 [run_baseline.py](../scripts/run_baseline.py) 中，仅修改 `baseline.json` 不会改变该矩阵。执行期间保持应用源码不变。

| 位置 | 查看内容 |
|---|---|
| `data/scifact-baseline/` | `metadata.json` 保存抽样 ID 与覆盖率；`index-manifests/` 保存索引身份、块数与导入计时 |
| `.agent/executions/execution-*/` | `plan.json`、各条件配置、命令和日志；用 `commands.json` 定位对应运行 |
| `.agent/runs/<run>/` | 请求与失败 JSONL、`repeat-*.json` 批次墙钟、资源采样、实际配置和数据副本 |
| `.agent/state/index-run-registry.json` | 首次导入来源 |

保留执行目录、运行目录及首次导入注册表。复算已有记录时，将下面的示例路径替换为实际执行目录：

```bash
"$PYTHON" scripts/summarize_baseline.py .agent/executions/execution-YYYYMMDD-HHMMSS
```

汇总写入 `.agent/results/`，不重新执行实验。实测数值、图表和回答示例见[本机基线实测报告](../reports/本机基线实测报告.md)。
