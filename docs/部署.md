# 部署与使用

## 1. 准备环境

需要 Linux / WSL、Python 3.12、PATH 中的 uv、Node.js 22 LTS / npm 10、Docker Engine 与 Compose，以及兼容 CUDA 13.2 的 NVIDIA 驱动；按模型预留显存和内存，磁盘建议至少留出 20 GB。

以下命令均在项目根目录执行。

## 2. 首次安装

创建项目环境，按 [requirements.in](../requirements.in) 和 [constraints.txt](../constraints.txt) 安装依赖，再下载固定版本模型、构建前端：

```bash
uv venv --python 3.12 .venv
uv pip install \
  --python .venv/bin/python \
  -c constraints.txt -r requirements.in \
  --extra-index-url https://download.pytorch.org/whl/cu132 \
  --extra-index-url https://download.pytorch.org/whl/cpu \
  --index-strategy unsafe-best-match
.venv/bin/python scripts/download_models.py
npm --prefix web ci
npm --prefix web run build
```

模型 ID 与 revision 由 [config/models.json](../config/models.json) 固定；缓存遵循 Hugging Face 标准的 `HF_HUB_CACHE` / `HF_HOME` / `XDG_CACHE_HOME`，默认 `~/.cache/huggingface/hub`，自定义时让下载与服务使用相同环境即可。

可选：使用已有环境时，在项目 `.env.webui` 写入 `PYTHON="/已有环境的绝对路径/bin/python"`，安装和下载命令也使用该解释器。启动优先级为环境变量 `PYTHON`、`.env.webui`、项目 `.venv/bin/python`。该文件不提交到 Git，由 Shell 执行，只填写可信内容。

## 3. 启动 WebUI

以后使用只需运行：

```bash
bash start-webui.sh
```

打开 **http://localhost:8765**，在“总览”分别启动 vLLM 和 Chroma，等待服务就绪。无需提前启动这两个服务；Chroma 启动时需要 Docker 引擎可用。WebUI 默认仅供本机访问。

## 4. 准备数据并使用

1. 进入“数据与索引”，创建自己的工作区并选中。
2. 选择 `prepare`，点击“提交数据任务”；完成后选 `small` 和 `index`，再次提交。
3. 进入“交互式问答”，选择同一工作区和层级，输入问题。
4. 批量运行时进入“实验任务”，选择工作区和实验类型；进度与结果在任务中查看。

`formal` 保存正式数据，可用于浏览和问答。数据准备、索引重建请在自己的工作区操作；重新准备会覆盖该工作区的数据，需要重新建索引。

实验条件与参数见[实验设计](实验设计.md)，正式结果见[本机基线实测报告](../reports/本机基线实测报告.md)。

## 5. 停止

先在“实验任务”取消自己的运行任务，等待结束，再在启动 WebUI 的终端按 Ctrl-C。关闭 WebUI 不会停止独立实验任务，也不会停止已启动的 vLLM 或 Chroma。

停止 Chroma（保留数据）：

```bash
bash scripts/chroma.sh stop
```

通过 CLI 启动的 vLLM，在其终端按 Ctrl-C。通过总览启动的 vLLM 会继续运行，需要停止时由启动者确认对应进程后手动结束。勿终止其他人使用的服务。

## 6. 可选：CLI 启动服务

需要手动管理服务时，可运行：

```bash
bash scripts/chroma.sh up
bash scripts/start-vllm.sh
```

vLLM 在前台运行，服务地址为 `127.0.0.1:8000`；Chroma 地址为 `127.0.0.1:8001`。WebUI 可以直接使用这些已启动的服务。

查看 Chroma 状态或日志：

```bash
bash scripts/chroma.sh status
docker compose -f compose.yaml logs --follow chroma
```

服务参数见 [config/server.json](../config/server.json)，修改后需重启 vLLM；更换向量模型或分块参数后，需在自己的工作区重新建立索引。

## 7. 常见问题

- **WebUI 提示未构建**：执行 `npm --prefix web ci` 和 `npm --prefix web run build`，再启动。
- **Chroma 启动失败**：检查 Docker 引擎是否启动、当前用户能否连接；WSL 使用 Docker Desktop 时确认已开启对应发行版集成。
- **vLLM 启动失败**：从“总览”进入服务日志，检查 GPU、驱动兼容性和可用显存。
- **找不到模型**：重新运行模型下载命令，确认下载与服务的 Hugging Face 缓存环境一致。
- **端口占用**：确认 8765、8000、8001 上运行的是哪个服务；已有项目服务可直接使用，停止进程前先确认归属。
- **Windows 浏览器无法访问 WSL 页面**：尝试 `http://127.0.0.1:8765`，并检查 WSL 的 localhost 转发设置。
