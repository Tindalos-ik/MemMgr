# 部署与运维

本文记录 MemMgr 面向大模型推理的长短期记忆协同管理研究中，本地部署与初测阶段的环境和使用方法，供项目成员复现、维护和迁移实验。命令均在 WSL 项目根目录执行；每个新终端先设置环境变量：

```bash
export PYTHON="${PYTHON:-$HOME/mycode/vLLM/.venv/bin/python}"
export UV="${UV:-$HOME/.local/bin/uv}"
export HF_HOME="$HOME/.cache/huggingface"
```

## 1. 环境与容量

| 项目 | 当前记录与建议 |
|---|---|
| 系统与工具 | Ubuntu 22.04 / WSL；Python 3.12.14；uv 0.12.12 |
| GPU 与内存 | RTX 4050，显存 6141 MiB；WSL 内存 7.6 GiB、交换空间 2 GiB |
| Docker | Docker Desktop 4.87.0；Engine 29.7.2 |
| 磁盘规划 | 部署前预留 15–20 GB；模型、依赖和镜像新增容量规划为 5–12 GB |

## 2. 安装依赖

本机部署所用的核心组件版本如下：

| 组件 | 版本 |
|---|---|
| vLLM | 0.29.0 |
| PyTorch | 2.13.0+cu132 |
| Transformers | 5.17.0 |
| Chroma 轻量客户端 | 1.5.3 |

[requirements.in](../requirements.in)提供安装入口，[constraints.txt](../constraints.txt)同时约束核心组件和安装前已有包。安装流程依次为预览、增量安装和依赖检查：

```bash
"$UV" pip install --python "$PYTHON" -c constraints.txt -r requirements.in --dry-run
"$UV" pip install --python "$PYTHON" -c constraints.txt -r requirements.in
"$UV" pip check --python "$PYTHON"
```


## 3. 模型与服务

### 模型下载和路径设置

| 用途 | 模型 | 固定 revision | 许可 |
|---|---|---|---|
| 回答生成 | Qwen/Qwen2.5-1.5B-Instruct | `989aa7980e4cf806f80c7fef2b1adb7bc71aa306` | Apache-2.0 |
| CPU 向量编码 | BAAI/bge-small-en-v1.5 | `5c38ec7c405ec4b44b94cc5a9bb96e735b38267a` | MIT |

下载工具读取 [models.json](../config/models.json) 中的固定模型版本。

```bash
"$PYTHON" scripts/download_models.py
```

当前模型缓存位置由 `download_models.py` 和 `start-vllm.sh` 中的本机设置决定。迁移时按目标环境修改缓存目录，并保持模型 ID、revision 与缓存快照一致。

### Chroma

Chroma 保存文档块与向量，为当前检索流程提供向量查询和持久化。

```bash
bash scripts/chroma.sh up
```

[compose.yaml](../compose.yaml)使用 `chromadb/chroma:1.5.3`，地址为 `127.0.0.1:8001`，命名卷 `memmgr_chroma_data` 挂载到 `/data`。启动命令等待健康状态，健康检查通过镜像内 bash 发送 HTTP 请求至 `/api/v2/heartbeat` 并检查状态码 200。

固定镜像摘要为 `sha256:cfd193653bd61076610730a09acae34ab85b5b6b1f5db4d944c17b5e8453658d`；官方说明见 [Chroma Docker 部署](https://docs.trychroma.com/guides/deploy/docker.md)。

使用 Docker Desktop 的主机启动桌面程序，并确认 WSL 内的 Docker CLI 可连接引擎。

### vLLM

```bash
bash scripts/start-vllm.sh
```

该命令在前台运行，保留此终端；数据处理与问答在另一个已设置环境变量的终端执行。

服务监听 `127.0.0.1:8000`，提供 OpenAI 流式接口。启动参数为 FP16、eager、上下文上限 2048 token、单序列调度、显存预算 80%。兼容变量为 `VLLM_USE_V2_MODEL_RUNNER=0` 和 `VLLM_USE_FLASHINFER_SAMPLER=0`，离线加载变量为 `HF_HUB_OFFLINE=1`、`TRANSFORMERS_OFFLINE=1`。

服务端 `max_num_seqs` 固定为 1。实验中的客户端并发 C=2、C=4 用于观察请求排队；服务端仍按单序列调度。

查看健康状态和集合数量：

```bash
"$PYTHON" scripts/service_status.py
```

命令会打印 vLLM 健康状态、Chroma 心跳和各集合的文本块数量。

## 4. 数据与实验

SciFact 是用于科学论断检索与核验的数据集。本地采用 [BEIR 检索版](https://huggingface.co/datasets/BeIR/scifact)，原始项目由 [AllenAI SciFact](https://github.com/allenai/scifact) 发布。当前数据包括论文标题与摘要、科学论断及其检索相关性标签。

| 数据部分 | 数量 | 本轮用途 |
|---|---:|---|
| 文献语料 | 5183 篇 | 构建检索索引 |
| 科学论断 | 1109 条 | 作为检索查询 |
| test 标注 | 300 条查询、339 对查询—文献关系 | 使用官方标签计算 Recall 与 nDCG |

例如检索 DdrB 论断时，系统先召回相关论文摘要，再将摘要作为证据交给模型组织回答。SciFact 数据按 CC-BY-SA-4.0 许可公开；完整语料可在本机处理，稳定的文献 ID 支持核对检索证据。本轮以静态文献检索建立基线，后续研究可加入长对话、时间序列和记忆写入更新数据。

[baseline.json](../config/baseline.json)固定正式实验的问题样本、模型版本与数据目录 `data/scifact-baseline`。单条问答可先建立 small 索引：

```bash
"$PYTHON" -m memmgr --config config/baseline.json prepare
"$PYTHON" -m memmgr --config config/baseline.json index --tier small
```

数据准备会校验官方 SciFact 压缩包，保存来源、许可、文档 ID 和相关性标签。索引采用 CPU BGE 归一化向量，文本块长度 384 token、重叠 32 token。集合签名包括语料校验和、模型版本和分块参数；导入结束检查文本块数量并执行检索。

运行正式实验前准备正式数据，随后由统一脚本完成三级索引和测量：

```bash
"$PYTHON" -m memmgr --config config/baseline.json prepare
"$PYTHON" scripts/run_baseline.py
```

新实验可按需使用统一基线脚本。本轮完整结果见[最终实验报告](../reports/baseline-report.md)，其中包括关键阶段统计、问答示例和结果适用范围。

## 5. 日常运维

```bash
bash scripts/chroma.sh status
bash scripts/chroma.sh restart
bash scripts/chroma.sh stop
docker compose -f compose.yaml logs --timestamps --follow chroma
```

Chroma 停止后保留命名卷。vLLM 前台进程通过 Ctrl-C 停止，重启使用原启动命令。

**数据删除说明：**下列命令会永久删除 `memmgr_chroma_data` 中的全部集合。操作前备份数据卷并确认恢复方式。

```bash
docker compose -f compose.yaml down
docker volume inspect memmgr_chroma_data
docker volume rm memmgr_chroma_data
```

## 6. 实验室迁移

迁移时根据目标节点的 GPU、显存和驱动确定模型配置，并准备 Python 3.12 与 CUDA 13.2 兼容环境。根目录依赖清单包含 vLLM、PyTorch、Transformers 和项目直接依赖；以下命令在预览后安装并检查依赖：

```bash
"$UV" venv --python /usr/bin/python3.12 "$HOME/envs/memmgr"
export LAB_PYTHON="$HOME/envs/memmgr/bin/python"
"$UV" pip install --python "$LAB_PYTHON" -c constraints.txt -r requirements.in \
  --extra-index-url https://download.pytorch.org/whl/cu132 \
  --index-strategy unsafe-best-match --dry-run
"$UV" pip install --python "$LAB_PYTHON" -c constraints.txt -r requirements.in \
  --extra-index-url https://download.pytorch.org/whl/cu132 \
  --index-strategy unsafe-best-match
"$UV" pip check --python "$LAB_PYTHON"
```

确认 CUDA 与驱动兼容后启动服务。Chroma 使用上述同一镜像摘要；迁移数据前备份持久卷，并在隔离副本上检查恢复结果。

7B 实验可选择 Qwen2.5-7B-Instruct，并为新模型固定 revision。同步更新模型下载清单、应用配置和启动脚本中的模型名称与路径；根据目标显存重新设置上下文长度、显存预算和调度并发，完成离线生成与持久化检查后开始新一轮测量。
